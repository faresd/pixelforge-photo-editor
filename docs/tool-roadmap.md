# Pixel professional toolbar roadmap

This matrix distills the two user-provided toolbar references into an implementation and test plan for Pixel. The references are visual inspiration and capability requirements; Pixel uses its own interaction design, names and icons where that improves browser accessibility.

The menu references and their complete categorized inventory are maintained in [`docs/menu-roadmap.md`](./menu-roadmap.md). That document records Edit, Image, Layer, Type, Select, Filter, View and Plugins workflows, including the Image Size dialog and the Filter submenu families.

## Current Pixel baseline

Implemented in this branch (production deployment follows the protected merge): Move, Crop, Brush, Pencil, Color Replacement, Eraser, Text, Rectangle, Ellipse, single-row and single-column marquee presets, layer properties, nondestructive per-layer brightness/contrast/saturation/hue/blur/Levels adjustments, rotate/flip, local/cloud project persistence, optional Cheaply session and production CI/CD. The supplied Cheaply artwork is used in the brand lockup beside an original cyan Pixel monogram.

The active implementation increment adds Hand, Zoom, Eyedropper, Paint Bucket, Gradient, Clone, Healing, Background Eraser, Magic Eraser, Dodge, Burn, Sponge, Smudge, rectangular/elliptical/single-row/single-column/lasso/polygonal-lasso and Magic Wand color selection, selection composition (replace/add/subtract/intersect), inversion, feather control and alpha-correct nondestructive masks. **Remove Background** adds a deterministic local edge-connected colour segmentation mask with persisted tolerance, source preservation and explicit limitations; it is not semantic subject detection. Brush, Eraser, Background Eraser, Clone, Healing, Dodge, Burn, Sponge and Smudge use tested bounded radial or sampled-colour primitives; pressure mapping is opt-in and backward-compatible with older drafts, clipped clone destinations preserve the corresponding source range, and queued pointer pressure survives asynchronous decode. Background and Magic Eraser use immutable source samples, tolerance-validated connected regions, transparent-edge normalization and one history commit per gesture. Dodge and Burn use deterministic luminance range masks; Sponge uses HSL vibrance while preserving alpha and transparent-edge bytes; Smudge samples an immutable source snapshot behind the drag direction, blends by Flow and radial coverage, preserves destination alpha and skips hidden RGB in transparent pixels. The O shortcut cycles the tonal trio, R activates Smudge, and settings survive local/project reload. Straight-segment Pen and Direct Selection now add editable path layers with local nodes, fill/stroke rendering, transformed node drags, history-safe cancellation and project round trips. It also adds persisted layer folders: group/ungroup, rename, collapse/expand, visibility, opacity and locking; Quick Mask and named saved selections; nondestructive RGB/per-channel Curves; and raster layer-mask controls for invert, disable/enable and removal while retaining immutable source pixels. Local and private-cloud persistence now validates document versions, migration metadata, revisions, project links and response envelopes before writes or state adoption, with an explicit v1-to-v2 migration registry and fail-closed malformed-response handling. The left palette uses two columns at normal editor widths and three columns at wide widths; its labels, shortcuts, focus order and touch targets are covered in desktop/mobile browser tests. The screenshot-only tool names (Artboard, Selection Brush, Frame, Cookie Cutter, Stamp, Red Eye and the remaining advanced tools) remain inventory entries, not claims of current behavior. Each tool and workspace operation must have a dedicated desktop and mobile browser acceptance test before merge. Pixel does not claim Photoshop equivalence while the remaining families are incomplete.

The straight-segment path slice is covered by six pure geometry tests and eight desktop/mobile browser acceptance runs. Those checks include deterministic bounds and serialization, representative fill pixels, Pen `P` activation, Direct Selection `A` node movement, undo/redo, lock rejection, Escape/touch cancellation, reload and project round trips. The full path contract is documented in [`docs/path-tool-contract.md`](./path-tool-contract.md); Bézier handles, freeform/curvature paths and path boolean operations remain staged.

Editable vertical type flow is covered by deterministic glyph-column and validation tests plus four desktop/mobile browser checks. The Type menu and Layers panel round-trip horizontal/vertical state through reload and project export, preserve editable source metadata, and disable orientation commands for raster or locked layers. The rendering and persistence contract is documented in [`docs/vertical-type-contract.md`](./vertical-type-contract.md); OpenType vertical shaping, punctuation alternates, type-on-path and text masks remain staged.

The current release gate records **196 pure tests** (the release-artifact check is run after `write-release.mjs`) and the existing full browser baseline plus focused acceptance for the account menu (4 desktop/mobile checks), multi-input batch export (6 desktop/mobile checks), accessibility/reduced motion (4 checks), selection refinement (4 checks), local conflict recovery (2 desktop/mobile checks), release status (8 desktop/mobile checks), vertical type (4 desktop/mobile checks) and worker encoding (2 desktop/mobile checks). Batch export covers successful ZIPs, mixed valid/invalid files, per-file failure reporting and Escape cancellation. Account acceptance covers anonymous local-only identity, stable avatar/sign-in routes, authenticated projects/profile/logout routes and outside-click/Escape recovery. Accessibility acceptance covers focus-visible rings and reduced motion on desktop and mobile. Conflict recovery covers strict revision gating and the Reload newer draft path without creating a new bookmark. Release status covers version display, matching release/readiness identity, degraded mismatches and offline local-editing fallback, polling recovery and status-cache bypass. Worker encoding covers bounded tile planning, OffscreenCanvas capability detection and a safe Canvas2D fallback. Every shipped tool increment must update this evidence and pass its focused desktop/mobile acceptance suite before merge.

## Extensive test contract

“Each implemented feature should come with extensive tests” is a release requirement. A feature means a tool, menu command, dialog behavior, persisted setting, import/export path or workspace mode—not only a large toolbar family. Tests should be added with the implementation and name the feature in their title.

| Test layer | Required coverage for every implemented feature | Evidence expected before enabling the menu/tool |
| --- | --- | --- |
| Pure behavior | Valid inputs, smallest useful canvas, transparent and opaque pixels, deterministic output, invalid settings and no-op/identity settings | Focused unit tests for geometry, selection algebra, color math, command validation or serialization |
| Document safety | Undo and redo, interaction with a selection/mask, hidden/locked layers, active-layer changes, concurrent gestures and cancellation | Browser or integration test proves source/editable layers and history remain correct |
| Persistence | Autosave/local reload, bookmark/project reopen, schema validation/migration and export/import round trip | Round-trip fixture compares editable properties, assets, masks and metadata rather than only a screenshot |
| Interaction | Keyboard shortcut, toolbar/menu activation, pointer/touch or pen fallback, focus order, Escape/outside-click recovery, disabled-state labeling | Desktop and mobile browser tests with accessible names and shortcut behavior |
| Visual/data correctness | Representative pixel/alpha assertions, dimensions, color/units/quality metadata and expected error state | Golden fixtures are deterministic and tolerate no silent clipping, flattening or upload |
| Scale/reliability | Large/odd aspect images, memory/time budget, worker cancellation, malformed file, storage/network failure and retry | Targeted performance/failure test or documented reason the feature is local-only |
| Release/live | Typecheck, lint, production build, full browser suite and deployed-revision smoke check | CI run identifies commit; live check verifies the enabled action and persisted result on the deployed revision |

Feature-specific additions are mandatory where applicable: raster tools require before/after pixel and alpha-edge fixtures; selections require replace/add/subtract/intersect/invert/feather and disconnected-region fixtures; vector/text tools require path/metrics round trips and fallback fonts; menus require complete enabled/disabled inventory and command scope tests; dialogs require cancel/invalid/locale/resize cases; AI or remote actions require consent, quota, privacy, offline and cancellation tests. Shared test helpers are encouraged, but one passing helper test does not count as coverage for every effect or command.

## Delivery gates

1. Add the data model before exposing a tool that needs persistence (selection paths, masks, paths, adjustment commands and history references).
2. Every tool gets an accessible toolbar control, a keyboard shortcut where one is defined, mobile pointer behavior and a focused acceptance test.
3. Every raster operation is undoable, preserves the original asset until an explicit destructive action, and has at least one representative pixel assertion.
4. Every persisted property is validated, migrated and round-tripped through local and private cloud project files.
5. CI must run the desktop/mobile browser suite before production promotion; live deployment evidence must identify the tested commit.
6. AI, cloud asset sources and large-image processing remain opt-in and require an explicit privacy, quota and performance contract.

## Implementation schedule

Work proceeds in dependency-ordered increments. A phase is complete only when its tools, persistence, desktop/mobile acceptance tests and live revision evidence satisfy the delivery gates above.

| Phase | Scope | Exit criteria |
| --- | --- | --- |
| 0 — Foundation | Toolbar registry, shortcuts, responsive two/three-column layout, tool state, undo/redo, local draft recovery, schema validation, test fixtures | Every registered tool has an accessible control; desktop/mobile grid layout, touch targets, reload/bookmark recovery and CI smoke suite are green |
| 1 — Core navigation and raster basics | Move, Hand, Zoom, Eyedropper, Paint Bucket, Gradient, Brush, Pencil, Eraser, Color Replacement | Extensive test contract for each tool: representative pixel/alpha tests, keyboard/touch gestures, undo, failures and draft round-trip |
| 2 — Selection, crop and folders | Rectangular/Elliptical/row/column marquee, Lasso family, Magic Wand, Quick/Object selection, Crop, Perspective Crop, Slice family, Quick Mask, editable layer folders | Selection algebra and feathering are deterministic; Reselect snapshots and validated affine Transform Selection preserve editable geometry, clip masks at canvas edges, and survive undo/reload/project export; Grow and Contract apply bounded centred alpha morphology (1–1,000 px) without changing source pixels and survive undo/reload/project export; one-pixel row/column masks plus freehand/polygonal selections and slices survive reload/export; folder state and group visibility/opacity/lock survive reload/export |
| 3 — Retouch and paint depth | Clone/Pattern Stamp, Healing/Spot Healing/Remove, Patch, Content-Aware Move, Red Eye, Mixer Brush, History Brush, Art History, Blur/Sharpen/Smudge, Dodge/Burn/Sponge | Clone, Healing, Dodge, Burn, Sponge and Smudge now have immutable source/pixel contracts, before/after fixtures, bounded memory checks, explicit undo and mobile touch cancellation; remaining retouch families and worker/tile command layers stay staged |
| 4 — Vector and typography | Pen family, Path/Direct Selection, parametric shapes, line/custom shape, vertical type, type masks, alignment and spacing | Straight-segment paths, editable anchors, shape parameters and text metrics round-trip; transformed fill/stroke and alpha pixels match fixtures; remaining Pen variants and type modes stay staged |
| 5 — Workspace and asset workflows | Foreground/background wells, color swap/defaults, screen modes, responsive toolbar customization, device/drop intake, export presets, account/session affordances and local batch export | Two-column/three-column layout and keyboard reachability pass desktop/mobile checks; anonymous artistic identity and optional Cheaply profile controls preserve local-first editing; local multi-input export passes ZIP/privacy/bounds/failure/cancellation tests; user customization remains a later persisted preference |
| 6 — Intelligent and scale features | Opt-in object/quick inference, remote asset providers, generation, large-image tiling, performance instrumentation | Privacy/quota disclosure, offline fallback, performance budgets and provider failure tests are documented |


The current increment covers Phase 1 navigation/sampling/fill/retouch groundwork, Photoshop-style shortcut cycles and document commands, persisted layer folders, editable text alignment/spacing, Color Balance, deterministic Sharpen/Add Noise, **Auto Tone/Contrast/Color**, and the first Phase 5 export-presets slice: local PNG, JPEG and WebP export with explicit quality, byte-size preview, JPEG transparency disclosure, bounded 1 KB–64 MB target-size search for JPEG/WebP, rendered-export metadata stripping, and persisted preferences. Auto corrections use fixed alpha-aware byte algorithms, store only validated flags, and have 9 pure tests plus 10 desktop/mobile acceptance runs covering menu/shortcut scope, representative pixels, transparent edges, source retention, undo/redo, local reload, project round trip, lock protection and flat-image no-op history protection; the full contract is in [`auto-adjustment-contract.md`](./auto-adjustment-contract.md). Color Balance uses separate shadow, midtone and highlight channels with an optional luminosity-preservation pass; Sharpen uses a bounded alpha-aware unsharp mask and Add Noise uses a seeded deterministic generator, so both remain editable metadata rather than baked source pixels. “Batch export history…” now renders all retained undo states into a local ZIP with sanitized filenames, a privacy-safe dimensions/byte-size manifest, CRC-32 archive validation and a 256 MB output guard; source assets and metadata are never copied. The standalone **multi-input batch exporter** now defines local PNG/JPEG/WebP processing for up to 64 selected files with per-file failure reporting, progress/cancellation, sanitized names, source-size/pixel/output bounds and a privacy manifest; editor exposure remains gated on desktop/mobile acceptance of real file selection and mixed results (see [`image-batch-contract.md`](./image-batch-contract.md)). Polygonal lasso now adds a click-to-place, close-by-first-vertex workflow with the same persisted polygon selection and nondestructive mask pipeline as freehand lasso; magnetic lasso remains planned. Reselect snapshots and Transform Selection now retain editable selection metadata, apply bounded affine matrices without baking source pixels, clip transformed masks to the canvas, and cover undo/reload/project round trips on desktop and mobile. The vector shape increment adds editable line and regular polygon layers (including fill/stroke, polygon side count and affine transforms) alongside rectangle and ellipse, with representative pixel assertions, undo/redo and mobile/desktop persistence coverage. Triangle/star/custom paths and path-anchor editing remain planned. Background and Magic Eraser now have immutable sampled-color primitives and Canvas integration with 12 pure tests plus six desktop/mobile acceptance runs covering contiguous islands, tolerance, alpha edges, keyboard cycling, touch cancellation and reload. Dodge, Burn and Sponge now have 12 pure tonal tests plus 14 desktop/mobile acceptance runs covering luminance ranges, exposure/flow, vibrance modes, alpha/transparent edges, active selections, transformed selection sampling, no-op history protection, stale-gesture cancellation, O cycling, settings persistence, representative pixels, undo/redo, locked-layer rejection and touch cancellation. Group blend compositing remains scoped for a later isolated renderer milestone; current group opacity and visibility are applied to each child layer while retaining the child blend mode. Menus now use roving keyboard focus: Arrow/Home/End navigation skips disabled roadmap entries, Escape restores the trigger, and desktop/mobile acceptance tests cover pointer and keyboard paths. Quick-mask and saved-selection files now have their own acceptance and live deployment gates. Image Size covers linked/independent pixel and physical units, resolution metadata, Fit To presets, locale-aware input, preview and explicit resampling; resolution-only edits retain pixels while resampling transforms editable layers and masks. Canvas Size covers all nine anchors with bounded translation-only resizing and no-op history protection; Trim scans the rendered composite with transparency or corner-color modes and per-side preservation; Reveal All expands around visible transformed layer/group extents while retaining conservative text and blur bounds. Canvas geometry has 14 pure cases and 14 desktop/mobile acceptance cases covering invalid values, cancellation, empty composites, undo, reload and translated-layer import. Remaining perspective crop, slicing, advanced transforms and Photoshop-only effects stay staged behind their own gates. Phases 3–6 are intentionally sequenced after the selection, mask, path and persistence contracts they depend on; this keeps the editor extensible without presenting unfinished Photoshop-equivalent controls as complete.
