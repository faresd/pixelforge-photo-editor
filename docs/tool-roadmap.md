# Pixel professional toolbar roadmap

This matrix distills the two user-provided toolbar references into an implementation and test plan for Pixel. The references are visual inspiration and capability requirements; Pixel uses its own interaction design, names and icons where that improves browser accessibility.

The menu references and their complete categorized inventory are maintained in [`docs/menu-roadmap.md`](./menu-roadmap.md). That document records Edit, Image, Layer, Type, Select, Filter, View and Plugins workflows, including the Image Size dialog and the Filter submenu families.

## Current Pixel baseline

Implemented in this branch (production deployment follows the protected merge): Move, Crop, Brush, Pencil, Color Replacement, Eraser, Text, Rectangle, Ellipse, single-row and single-column marquee presets, layer properties, nondestructive per-layer brightness/contrast/saturation/hue/blur/Levels adjustments, rotate/flip, local/cloud project persistence, optional Cheaply session and production CI/CD. The supplied Cheaply artwork is used in the brand lockup beside an original cyan Pixel monogram.

The active implementation increment adds Hand, Zoom, Eyedropper, Paint Bucket, Gradient, Clone, Healing, rectangular/elliptical/single-row/single-column/lasso/polygonal-lasso and Magic Wand color selection, selection composition (replace/add/subtract/intersect), inversion, feather control and alpha-correct nondestructive masks. It also adds persisted layer folders: group/ungroup, rename, collapse/expand, visibility, opacity and locking; Quick Mask and named saved selections; and nondestructive RGB/per-channel Curves. The screenshot-only tool names (Artboard, Selection Brush, Frame, Cookie Cutter, Background Eraser, Magic Eraser, Stamp, Red Eye and the remaining advanced tools) are inventory entries, not claims of current behavior. Each tool and workspace operation must have a dedicated desktop and mobile browser acceptance test before merge. Pixel does not claim Photoshop equivalence while the remaining families are incomplete.

## Extensive test contract

“Each implemented feature should come with extensive tests” is a release requirement. A feature means a tool, menu command, dialog behavior, persisted setting, import/export path or workspace mode—not only a large toolbar family. Tests should be added with the implementation and name the feature in their title.

| Test layer | Required coverage for every implemented feature | Evidence expected before enabling the menu/tool |
| --- | --- | --- |
| Pure behavior | Valid inputs, smallest useful canvas, transparent and opaque pixels, deterministic output, invalid settings and no-op/identity settings | Focused unit tests for geometry, selection algebra, color math, command validation or serialization |
| Document safety | Undo and redo, interaction with a selection/mask, hidden/locked layers, active-layer changes, concurrent gestures and cancellation | Browser or integration test proves source/editable layers and history remain correct |
| Persistence | Autosave/local reload, bookmark/project reopen, schema validation/migration and export/import round trip | Round-trip fixture compares editable properties, assets, masks and metadata rather than only a screenshot |
| Interaction | Keyboard shortcut, toolbar/menu activation, pointer/touch or pen fallback, focus order, Escape/outside-click recovery, disabled-state labeling | Desktop and mobile browser tests with accessible names and shortcut behavior |
| Visual/data correctness | Representative pixel/alpha assertions, dimensions, color/units/quality metadata and expected error state | Golden fixtures are deterministic and tolerate no silent clipping, flattening or upload |
| Scale/reliability | Large/odd aspect images, memory/time budget, worker cancellation, malformed file, storage/network failure and retry | Targeted performance/failure test or documented reason the feature is local-only |
| Release/live | Typecheck, lint, production build, full browser suite and deployed-revision smoke check | CI run identifies commit; live check verifies the enabled action and persisted result on the deployed revision |

Feature-specific additions are mandatory where applicable: raster tools require before/after pixel and alpha-edge fixtures; selections require replace/add/subtract/intersect/invert/feather and disconnected-region fixtures; vector/text tools require path/metrics round trips and fallback fonts; menus require complete enabled/disabled inventory and command scope tests; dialogs require cancel/invalid/locale/resize cases; AI or remote actions require consent, quota, privacy, offline and cancellation tests. Shared test helpers are encouraged, but one passing helper test does not count as coverage for every effect or command.

## Delivery gates

1. Add the data model before exposing a tool that needs persistence (selection paths, masks, paths, adjustment commands and history references).
2. Every tool gets an accessible toolbar control, a keyboard shortcut where one is defined, mobile pointer behavior and a focused acceptance test.
3. Every raster operation is undoable, preserves the original asset until an explicit destructive action, and has at least one representative pixel assertion.
4. Every persisted property is validated, migrated and round-tripped through local and private cloud project files.
5. CI must run the desktop/mobile browser suite before production promotion; live deployment evidence must identify the tested commit.
6. AI, cloud asset sources and large-image processing remain opt-in and require an explicit privacy, quota and performance contract.

## Implementation schedule

Work proceeds in dependency-ordered increments. A phase is complete only when its tools, persistence, desktop/mobile acceptance tests and live revision evidence satisfy the delivery gates above.

| Phase | Scope | Exit criteria |
| --- | --- | --- |
| 0 — Foundation | Toolbar registry, shortcuts, responsive one/two-column layout, tool state, undo/redo, local draft recovery, test fixtures | Every registered tool has an accessible control; reload/bookmark recovery and CI smoke suite are green |
| 1 — Core navigation and raster basics | Move, Hand, Zoom, Eyedropper, Paint Bucket, Gradient, Brush, Pencil, Eraser, Color Replacement | Extensive test contract for each tool: representative pixel/alpha tests, keyboard/touch gestures, undo, failures and draft round-trip |
| 2 — Selection, crop and folders | Rectangular/Elliptical/row/column marquee, Lasso family, Magic Wand, Quick/Object selection, Crop, Perspective Crop, Slice family, Quick Mask, editable layer folders | Selection algebra and feathering are deterministic; Reselect snapshots and validated affine Transform Selection preserve editable geometry, clip masks at canvas edges, and survive undo/reload/project export; one-pixel row/column masks plus freehand/polygonal selections and slices survive reload/export; folder state and group visibility/opacity/lock survive reload/export |
| 3 — Retouch and paint depth | Clone/Pattern Stamp, Healing/Spot Healing/Remove, Patch, Content-Aware Move, Red Eye, Mixer Brush, History Brush, Art History, Blur/Sharpen/Smudge, Dodge/Burn/Sponge | Before/after fixtures, bounded memory, source preservation, explicit undo and mobile pressure fallback |
| 4 — Vector and typography | Pen family, Path/Direct Selection, parametric shapes, line/custom shape, vertical type, type masks, alignment and spacing | Paths, anchors, shape parameters and text metrics round-trip; fill/stroke and mask pixels match fixtures |
| 5 — Workspace and asset workflows | Foreground/background wells, color swap/defaults, screen modes, toolbar customization, device/drop intake, export presets | Preferences persist safely, Escape recovers fullscreen, accessibility checks pass, export is deterministic |
| 6 — Intelligent and scale features | Opt-in object/quick inference, remote asset providers, generation, large-image tiling, performance instrumentation | Privacy/quota disclosure, offline fallback, performance budgets and provider failure tests are documented |


The current increment covers Phase 1 navigation/sampling/fill/retouch groundwork, Photoshop-style shortcut cycles and document commands, persisted layer folders, editable text alignment/spacing, Color Balance, deterministic Sharpen/Add Noise, and the first Phase 5 export-presets slice: local PNG, JPEG and WebP export with explicit quality, byte-size preview, JPEG transparency disclosure, bounded 1 KB–64 MB target-size search for JPEG/WebP, rendered-export metadata stripping, and persisted preferences. Color Balance uses separate shadow, midtone and highlight channels with an optional luminosity-preservation pass; Sharpen uses a bounded alpha-aware unsharp mask and Add Noise uses a seeded deterministic generator, so both remain editable metadata rather than baked source pixels. “Batch export history…” now renders all retained undo states into a local ZIP with sanitized filenames, a privacy-safe dimensions/byte-size manifest, CRC-32 archive validation and a 256 MB output guard; source assets and metadata are never copied. Polygonal lasso now adds a click-to-place, close-by-first-vertex workflow with the same persisted polygon selection and nondestructive mask pipeline as freehand lasso; magnetic lasso remains planned. Reselect snapshots and Transform Selection now retain editable selection metadata, apply bounded affine matrices without baking source pixels, clip transformed masks to the canvas, and cover undo/reload/project round trips on desktop and mobile. The vector shape increment adds editable line and regular polygon layers (including fill/stroke, polygon side count and affine transforms) alongside rectangle and ellipse, with representative pixel assertions, undo/redo and mobile/desktop persistence coverage. Triangle/star/custom paths and path-anchor editing remain planned. Group blend compositing remains scoped for a later isolated renderer milestone; current group opacity and visibility are applied to each child layer while retaining the child blend mode. Menus now use roving keyboard focus: Arrow/Home/End navigation skips disabled roadmap entries, Escape restores the trigger, and desktop/mobile acceptance tests cover pointer and keyboard paths. Quick-mask and saved-selection files now have their own acceptance and live deployment gates. Image Size covers linked/independent pixel and physical units, resolution metadata, Fit To presets, locale-aware input, preview and explicit resampling; resolution-only edits retain pixels while resampling transforms editable layers and masks. Canvas Size covers all nine anchors with bounded translation-only resizing and no-op history protection; Trim scans the rendered composite with transparency or corner-color modes and per-side preservation; Reveal All expands around visible transformed layer/group extents while retaining conservative text and blur bounds. Canvas geometry has 14 pure cases and 14 desktop/mobile acceptance cases covering invalid values, cancellation, empty composites, undo, reload and translated-layer import. Remaining perspective crop, slicing, advanced transforms and Photoshop-only effects stay staged behind their own gates. Phases 3–6 are intentionally sequenced after the selection, mask, path and persistence contracts they depend on; this keeps the editor extensible without presenting unfinished Photoshop-equivalent controls as complete.


## Reference extraction notes

The first reference groups tools into Move and Selection, Crop and Slice, Measurement, Retouching and Painting, Drawing and Type, Navigation, toolbar editing, colors, Quick Mask, screen modes and image generation. The second reference names the individual tools and shortcuts listed above. Tool names are recorded for planning and compatibility vocabulary; Pixel's UI remains free, anonymous by default and locally private.
